## 1. 方案 A：只给代码（推荐，最干净）

我这边出包：

```bash
node scripts/package-release.cjs
# → C:\Users\HW\Desktop\qwen-FlowMate\FlowMate-v0.2-源码包.zip
```

对方拿到后（前置：装好 **Node.js 24 或更高**，`node -v` 确认；pnpm 可用 `npm i -g pnpm`）：

```bash
cd FlowMate
cp .env.example .env        # 想启用 AI 就填模型三件套，不填也能跑
pnpm install                # 依赖全部来自 npm 官方源，无需 PostgreSQL / Redis / Docker
pnpm build                  # 类型检查 + 编译后端 + 打包前端
pnpm seed                   # 灌演示数据（2 组织 / 3 团队 / 4 账号 / 9 个示例文件）
pnpm start                  # http://localhost:8080
```

要点：`node:sqlite` 是 Node 内置的，**对方不需要装任何数据库**；正文抽取、全文检索、事务、外键都由它承担。

## 2. 方案 B：连演示数据一起给（对方少跑一步 seed）

```bash
node scripts/package-release.cjs --with-data
# → FlowMate-v0.2-含数据包.zip（含 data/ 与 storage/）
```

对方执行 `pnpm install && pnpm build && pnpm start`，**跳过 `pnpm seed`**，打开就是你这台机器上的状态（含已抽取好的正文、已建好的会话与任务）。

注意两点：
- 数据包里的账号密码仍是 `Flowmate#2026`（除非改过 `SEED_PASSWORD` 重新 seed）。
- 对方浏览器如果访问过旧版本，localStorage 里可能残留旧组织 ID——服务端已做回落处理（不会像之前那样报「不属于该组织」），但刷新一次更干净。

## 3. 方案 C：不打包，现场局域网演示（最快）

你这台机器 `pnpm start`，别人连同一 WiFi 直接开 `http://<你的内网IP>:8080`。启动日志会打印地址（IP 是 DHCP 动态的，每次以日志为准）。首次需放行防火墙：

```powershell
New-NetFirewallRule -DisplayName "FlowMate 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

打不开时的判断顺序：① 对方 `ping <你的IP>` 不通 → 网络开了 AP 隔离（换手机热点或同一路由的普通网段）；② ping 通但页面打不开 → 防火墙没放行或端口不对；③ 页面能开但接口报错 → 看服务端控制台日志（有 `[http]` 与 `[client]` 两类，后者是前端上报的堆栈）。

## 4. 密钥怎么办（重要）

`.env` 被打包脚本硬性排除，不会随包外发。接收方要启用 AI 能力，自己建 `.env` 填三行：

```
MODEL_BASE_URL=https://<网关地址>
MODEL_API_KEY=***
MODEL_NAME=<网关上真实可用的模型名>
```

本项目已针对推理型网关做了两件必要适配，交接时请一并说明，否则对方换成别家网关容易踩坑：

- `MODEL_JSON_MODE`：网关支持 `response_format: json_object` 才设 1，否则设 0（靠提示词 + 容错解析）。
- `MODEL_EXTRA_PARAMS`：厂商专有参数原样透传。例如当前这个网关必须写 `{"thinking":{"type":"disabled"}}`——不关思考时，模型会把输出额度全花在推理上、`content` 返回空，提取就会失败。
- 模型输出契约是**容错归一化**的：模型把 `exec` 写成 `fs.read`、把 `kind` 写成「待办」、返回裸数组，都会被映射到内部枚举；认不准的一律降级为「只读」或「待澄清」，不会自动变成写操作。

不填密钥时应用照常可用：Agent 走本地确定性规划器（界面与 RunStep 全程标注「未调用模型」），纪要提取会明确返回 503 并可重试，**不会伪造候选**。

## 5. 交给别人前的自检清单

```bash
pnpm typecheck                                   # 前端 + 后端 0 错误
pnpm test                                        # 28 条核心不变量
node scripts/check-inserts.cjs server/modules/*/*.ts scripts/seed.ts   # 79 条 INSERT 列数/占位符自检
pnpm build && pnpm seed && pnpm start &
node tests/e2e.mjs                               # 69 条端到端断言
node tests/timeout-suspend.cjs                   # 12 条共同确认时序（约 4 分钟，等真实 tick）
node tests/org-fallback.cjs                      # 组织回落与跨组织隔离
node scripts/cdp-check.cjs                       # 浏览器冒烟：点击主路径，捕获前端异常
curl http://localhost:8080/api/v1/health         # DB / 队列 / 存储 / WS 分开报活
```

## 6. 数据怎么备份与迁移

```bash
pnpm backup     # → backups/<时间戳>/backup.zip（DB 三文件 + storage 全量）+ manifest.json
pnpm restore    # 恢复最近一次备份（恢复前自动把当前数据挪到 backups/pre-restore-*/）
```

想把「干净演示态」交给别人：`pnpm run seed:reset` 后立刻 `pnpm backup`，把 `backups/<时间戳>/backup.zip` 一起给；对方解压 + install + build 后跑一次 `pnpm restore <该目录>` 即可复现。
