## 4. 本轮发现并修复的真实缺陷（不是测试脚本问题）

| 缺陷 | 影响 | 修复 |
| --- | --- | --- |
| `resolveAcl` 对文件的祖先目录按 `resource_type='file'` 查 ACL | 队友打不开团队目录里的文件（403），连带提交产物、共同确认全部走不通 | 按每个 id 的真实类型查（file / folder），单测与 e2e 均覆盖 |
| `resolveAcl` 对目录资源查询不存在的 `folder_id` 列 | 会话绑定目录、移动、分享等一律 500 | 目录走 `parent_id AS folder_id` |
| `wouldCreateCycle` 方向写反 | 「把父目录移进自己的子目录」可通过校验，目录链成环 | 改为在待移动节点的子树里查找目标父级 |
| `createFile` 先写 `files.current_version_id` 再写版本 | 循环外键导致上传直接失败 | 先 NULL 建文件 → 建版本 → 回填指针 |
| Agent 草稿同名冲突直接抛错（两槽并发时撞 UNIQUE） | `formal_change` 子任务失败，共同确认提案根本生成不出来 | Agent 来源自动占唯一名 + 工具层带 Run 短号重试；人的上传仍给建议名不覆盖 |
| docx/pptx 抽取器按错误的节点形状递归 | 字符串属性被逐字符展开 → 栈溢出，Office 正文完全抽不出来 | 按 fast-xml-parser v4 `preserveOrder` 真实形状（`#text` / `:@` / 子数组）重写遍历 |
| PDF 抽取未给 worker 文件路径 | pdfjs v4 在 Node 下报「No GlobalWorkerOptions.workerSrc」 | 解析真实 worker 路径注入 |
| 8 处 INSERT 列数与占位符不匹配（tasks / discovery_imports / folder_watch_configs / file_versions / runs / artifacts 等） | 建任务、导入、建 Run 直接 500 | 逐条对齐，并留下 `scripts/check-inserts.cjs` 静态自检（83 条全通过） |
| 越界读取只在会话文本里提一句 | C08 演示看不到防护生效 | 路径读取改走工具层，被拒时留下 `denied` RunStep |
| `AuthGuard` 把客户端带来的组织 ID 当硬校验 | 重新灌种子后组织 UUID 变了，浏览器 localStorage 里的旧 ID 让**登录与 /auth/me 本身**返回 403「不属于该组织」，前端再没机会自我纠正（用户实测发现） | 组织 ID 降级为「用户偏好」：非法/过期时回落到本人所属组织；回落目标只会是本人确实属于的组织，跨组织隔离仍然成立。新增 `tests/org-fallback.cjs` 10 项断言（含数据隔离与四个演示账号） |

## 5. 共同确认时序（`tests/timeout-suspend.cjs`，12 项）

做法：造出真实的待确认提案后，把提醒 / 挂起时间点改到过去，等 60 秒一轮的 tick 生效——等价于时间真的流逝，而不是把逻辑改成通过。

- 到期先提醒：`reminder_count` 由 0 变 1，状态仍是 `pending_approval`（**提醒不等于同意**）
- 提醒以应用内通知送达相关指令人（本版无邮件 / IM 通道）
- 超阈值 → `suspended`（界面显示「已搁置·等待 XX 确认」），**没有任何自动通过路径**
- 挂起期间正式文件版本数仍为 1（一个字节都没写）
- 挂起后无 Run 残留占用执行槽
- 协调者 `wake` → 回 `pending_approval`；`void` → `cancelled` 并留痕
- 他人先改基准 → 提案自动 `stale`
- 用旧 `diff_hash` 批准 → `409 PROPOSAL_STALE`（禁止旧签名批准新内容）
- `regenerate-diff` → `revision 1→2`、确认计数清零
- 按新差异重新确认后才会真正写入，且只新增一个版本（版本数 3：初始 → 他人改动 → 提案提交）

## 6. 备份与恢复演练（C21）

`pnpm backup` 产出 `backups/<时间戳>/backup.zip`（1.56 MB，含 DB 三个文件 + storage 全量）与 `manifest.json`；停服后 `pnpm restore` 恢复（恢复前自动把当前数据挪到 `backups/pre-restore-*/`）。核对结果：任务数 4、目录内文件数 12、提案数 5 与备份前完全一致，恢复后文件仍可正常下载（HTTP 200，2410 字节）。

**本轮修掉的缺陷**

| 缺陷 | 表现 | 修复 |
| --- | --- | --- |
| 推理型网关把输出额度花在思考上，`content` 为空 | 纪要提取报「模型未产出可校验结果」，Agent 规划 422 | 新增 `MODEL_EXTRA_PARAMS` 原样透传厂商参数（此网关需 `{"thinking":{"type":"disabled"}}`）；`MODEL_MAX_TOKENS=0` 表示不下发上限；错误信息区分「只有思考没有答案」 |
| 模型自由发挥枚举值 | `exec` 写成 `fs.read`、`kind` 写成「待办」、返回裸数组、`parallel_reason: null` → 严格 schema 全部 reject | 规划与提取两侧都改为容错归一化：同义词映射到内部枚举，认不准的降级为「只读」或「待澄清」，绝不降级成写操作 |
| 未绑定目录的会话被规划成写草稿 | 问答直接 `FORBIDDEN` 失败，用户视角就是「Agent 不能用」 | 规划出口强制：无绑定 ⇒ 只产生一条 `answer` 子任务，不出现任何写文件步骤 |
| 用户明确要改正式文件时模型只规划到草稿 | 请求以「成功」收场但提案从未生成（C10c 失败） | 抽出 `ensureFormalStep()`，在「新建请求」与「补澄清后重规划」两处都做结构性保证 |
| 全局搜索文件分组契约不一致 | 后端返回裸数组、前端读 `groups.files.items` → 搜索永远显示无命中 | 统一为 `{items, more}`；Workspace 搜索与全局搜索同时恢复 |
| `candidate_tasks` 两处列序/外键错误 | `status` 落到 NOT NULL 列为 null、`source_item_id` 写了分块编号 `b3` | 修正占位符顺序；建立 `block_id → source_items.id` 映射后写真实 ID |
| `useUrlState` 清空参数时删键 | `params.q` 变 undefined → `searchQ.trim()` 抛错 → 切换空间/搜索整页崩溃 | 参数永远保留默认值；并补上前端错误上报与错误边界（崩溃可见、可重试、堆栈进服务端日志） |

**模型配置说明（交接必读）**：`MODEL_NAME` 用网关实际接受的名字（`Qwen-FlowMate` 被该网关拒绝，它只接受 `deepseek-flash` / `deepseek-v4-pro`）；`MODEL_JSON_MODE=1`（该网关支持 `response_format`）；`MODEL_EXTRA_PARAMS={"thinking":{"type":"disabled"}}`。
